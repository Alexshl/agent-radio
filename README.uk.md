# agent-radio

[English](README.md) | Українська

«Особисте радіо» для ШІ-агентів, яке ви розгортаєте самі, з підтримкою кількох користувачів. У кожного користувача своя станція: музика (ретрансляція інтернет-радіо,
плейлист зі спільної фонотеки або тиша). Коли ваш агент завершує роботу, він надсилає коротке текстове зведення, сервер озвучує його й пускає у вашу
станцію, приглушуючи музику. Якщо ніхто не слухає, повідомлення пропускається (без озвучення та черги) і лишається в історії. Агент може надіслати й готове аудіо
(зведений мікс, зразок голосу): воно грає за повністю вимкненої музики.

## Як це працює

```
 агенти (Claude Code, скрипти)                       слухачі
   agent-radio say / play                       телефон (VLC), браузер, будь-який плеєр
            |                                              ^
            v  HTTPS + API-ключ                            | /stream/<id>.mp3?k=<токен>
   +--------------------+  текст   +-----------+   +-------------+
   | app (Hono + SQLite)|--------->|    TTS    |   |   Icecast   |
   | вебінтерфейс, API, |  кліп    | azure /   |   | точка на    |
   | вхід, фонотека,    |<---------| openai /  |   | кожну       |
   | історія            |          | gemini /  |   | станцію     |
   +--------------------+          | piper     |   +------^------+
            | керування            +-----------+          |
            v                                             |
   +--------------------+  черга голосу (музика тихіше)   |
   |     Liquidsoap     |  черга файлів (музика вимк.) ---+
   | станція на кожного |  музика: ретрансляція | плейлист | тиша
   +--------------------+
```

- **Агенти** звертаються до `/api/say` і `/api/play` з ключем для кожного комп'ютера (або використовують команду `agent-radio` і скіл Claude з `client/`).
- **TTS**: Azure Neural, OpenAI, Gemini або Piper (офлайн, за замовчуванням і як запасний варіант). Ключі зберігаються зашифрованими (AES-GCM).
- **Liquidsoap** мікшує станції, **Icecast** роздає звук, застосунок віддає потік за секретним токеном користувача.
- **Вебінтерфейс** (React): керування станцією, фонотека й плейлисти, ключі агентів, історія, адмінка. Тексти інтерфейсу: `src/client/i18n`.

## Швидкий старт

Потрібен Docker. Або скажіть своєму ШІ-агентові: «візьми цей репозиторій і встанови радіо» (його ведуть [INSTALL.md](INSTALL.md) і `skills/agent-radio-setup`).

```sh
cp .env.example .env     # ADMIN_EMAIL, ADMIN_PASSWORD (12+ символів), MUSIC_DIR, PUBLIC_URL, паролі icecast
docker compose up -d --build
```

Відкрийте `http://localhost:8791`, увійдіть, на сторінці **Підключити агента** створіть ключ і вставте промпт у Claude на потрібному комп'ютері
(він виконає `curl -fsSL <ваш сервер>/client/install.sh | sh`). Для доступу з телефона використовуйте Cloudflare Tunnel або Tailscale (див. INSTALL.md) і задайте
`PUBLIC_URL`. Слухайте через VLC (грає з вимкненим екраном); браузери грають лише на передньому плані.

```sh
agent-radio status                      # слухачі та мова, якою писати зведення
agent-radio say "Сборка готова, тесты проходят"
agent-radio play mix.mp3 "Вот новый микс"
```

## Автоматичні зведення

`install.sh` може додати правило до `~/.claude/CLAUDE.md` (агент озвучує зведення наприкінці завдання) і, за бажання, хук «radio guard»
(`AGENT_RADIO_HOOKS=1` або відповідь `y` на запитання). Скрипт встановлюється в `~/.local/share/agent-radio/agent-radio-hook.sh` і підключається до
`~/.claude/settings.json` як хук `Stop` та хук `PreToolUse` для `AskUserQuestion` (решта налаштувань зберігається, створюється резервна копія).
Якщо ви слухаєте радіо, а від вашого останнього повідомлення сесія не викликала `agent-radio say|play`, хук один раз блокує завершення ходу
(або запитання) і просить агента спершу надіслати зведення з 1–4 речень. Без вашої згоди `settings.json` не чіпається.

## Довідник API

Для агентів: заголовок `Authorization: Bearer ar_...` (ключі створюються у вебінтерфейсі). Помилки: `{"error": "<код>", "message": "..."}`.

### `POST /api/say`

```sh
curl -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
     -d '{"session":"invoa","host":"devbox","text":"Миграция готова"}' $URL/api/say
```
`text` до 2000 символів. Відповідь `{"status":"aired"|"skipped","listeners":N}`. Якщо ніхто не слухає: `skipped`, без озвучення. Ліміти: 10 на хвилину на ключ і годинний
ліміт адміністратора на користувача (`429`). Якщо ввімкнено «Називати сесію», кліп починається словами «Сесія <ім'я>.» мовою користувача.

### `POST /api/play` (multipart/form-data)

```sh
curl -H "Authorization: Bearer $KEY" -F file=@mix.mp3 -F title="Микс 3" -F intro="Вот новый микс" -F session=tu-mani $URL/api/play
```
Поля: `file` (mp3, wav, flac, ogg, opus, m4a, aac; за замовчуванням до 95 МБ (менше за ліміт запиту Cloudflare у 100 МБ) і 20 хвилин, налаштування адміна), `title`, `intro` (промовляється перед файлом), `session`, `host`.
Файл перевіряється ffprobe, нормалізується приблизно до -14 LUFS і кодується в mp3 192k, 44,1 кГц, стерео. Він завжди зберігається в історії (7 днів) і виходить в ефір,
лише якщо зараз хтось слухає; поки він грає, музика вимкнена, а голосові повідомлення чекають. Відповідь `{"status","listeners","id","title","durationSec"}`;
помилки: `400 file_required|no_audio`, `413 too_large|too_long`, `415 unsupported_type`.

### `GET /api/status`

`{"up","listeners","title","lang","speakSession","chime","voice","station":{...}}`. `lang` (`uk`, `ru`, `en`) — мова, якою потрібно писати зведення.

### `PUT /api/station/source`

`{"type":"relay","url":"https://..."}`, `{"type":"playlist","dir":"Jazz"}`, `{"type":"userplaylist","playlistId":"..."}` або `{"type":"silence"}`; застосовується одразу.

### Потоки

`GET /stream/<stationId>.mp3?k=<listenToken>` і `.m3u`. Хибний токен дає 404. «Змінити посилання» в інтерфейсі створює новий токен.

## Деплой без обриву слухачів

Рушій (Liquidsoap) та Icecast тримають з'єднання всіх слухачів: їх перезапуск обриває всі плеєри. Зміни застосунку викочуйте лише командою
`docker compose up -d --build app`; `liquidsoap`/`icecast` чіпайте, лише якщо змінився `liquidsoap/radio.liq` або їхній образ, і попереджайте про це.
Вебплеєр перепідключається сам (1 с, 2 с, 5 с, потім кожні 10 с приблизно 5 хвилин, а також при поверненні на вкладку та появі мережі);
VLC та інші плеєри зазвичай ні: слухачам потрібно знову натиснути play. Томи `data` / `shared` не видаляйте (`down -v` лише для dev-стенда).

### Локальні нейроголоси (необов'язковий сервіс)

`tts-local`: Python 3.11 на CPU (відеокарта AMD gfx803 не підтримується ROCm / PyTorch), внутрішній HTTP API (`GET /voices`, `POST /synthesize`).
Вмикається так: `COMPOSE_PROFILES=local-tts` у `.env` і `docker compose up -d --build tts-local`. Перший запуск завантажує кілька ГБ моделей у том `ttsmodels`.
Рушії: `styletts2` (українська, MIT), `silero` (російська, **CC BY-NC-SA 4.0, лише некомерційне використання**), `f5` (російська, експериментальний, `TTS_LOCAL_F5=1`,
на CPU дуже повільний). Увімкнення для користувачів: Адмінка > Голос і TTS > «Локальні нейроголоси». Якщо синтез триває довше за 15 с, `POST /api/say` відповідає
`202 queued`, і повідомлення вийде в ефір, коли буде готове (якщо слухачі ще є). Подробиці та результати вимірювань: README.md.

## Безпека

- Акаунти лише за запрошенням; паролі PBKDF2-SHA256; сесійна cookie httpOnly SameSite=Lax (Secure за https); перевірка Origin для кожного запиту, що змінює дані,
  з cookie; обмеження спроб входу за IP та поштою. API-ключі й посилання-запрошення зберігаються у вигляді гешів. Ключі провайдерів шифруються `APP_SECRET`.
- За замовчуванням застосунок слухає лише 127.0.0.1; TLS забезпечує тунель (Cloudflare Tunnel, Tailscale). Не відкривайте порт застосунку в інтернет напряму.
- Посилання на потоки (пресети та власні посилання) завантажує застосунок, а не рушій: рушій працює в docker-мережі без виходу в інтернет. Застосунок приймає лише
  публічні адреси (перевіряється кожна відповідь DNS, з'єднання прив'язане до перевіреної адреси, редиректи перевіряються заново) і передає звук рушієві внутрішнім
  портом, який не публікується.
- Про вразливості повідомляйте приватно через GitHub Security Advisories (вкладка Security → «Report a vulnerability»).
